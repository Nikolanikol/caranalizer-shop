# Скрапер skywheel.kr — колёсные диски

Второй донор, не считая partsfit. Устроен принципиально иначе, и разница важнее сходства.

```bash
npm run skywheel:scrape     # листинг + все карточки, ~2 минуты
npm run skywheel:classify   # разбор в записи товара + отчёт о покрытии
npm run skywheel:tables     # таблицы под Supabase
npm run skywheel:verify     # 17 проверок базы (с --prod — по боевой)
npm run skywheel:load       # заливка (с --prod — в боевую)
```

## Выкатка на прод: порядок обратного не терпит

Тот же, что у partsfit, и по той же причине: витрина читает `skywheel_*`, и код
на сервере раньше таблиц положит раздел дисков.

```
1. миграция на VPS   supabase/migrations/20260829000000_skywheel_wheels.sql
                     через SQL Editor — руками, не `db push`
2. проверка          npm run skywheel:verify -- --prod
3. заливка           npm run skywheel:load   -- --prod
4. проверка ещё раз  npm run skywheel:verify -- --prod
5. и только теперь   деплой кода
```

**`supabase db push` и `db reset` на прод не запускать никогда** — база общая
с kmotors, `reset` снёс бы её каталог целиком.

Шаг 2 до заливки — не перестраховка. Прогон по пустой базе сам переходит в режим
«только схема, права, ограничения и RLS», а содержательные проверки помечает
пропущенными. Именно так и ловится забытая миграция: она видна одной строкой,
а не двадцатью невнятными отказами.

Проверка сама себя не жалеет: **отказ не должен выглядеть галочкой.** Первый же
прогон по проду это и показал — отсутствующая таблица отдаёт `null` без ошибки,
и три проверки печатали «✓ skywheel_wheel_images — null строк», а чтение анонимным
ключом зеленело на несуществующих таблицах. Отличать «ограничение сработало»
от «таблицы нет» приходится по коду ошибки: 23503/23505/23514 — ограничение,
42P01/PGRST205 — миграции нет.

## Что это за источник

`skywheel.kr/board/bbs/board.php?bo_table=market` — **доска объявлений**, а не каталог
поставщика. Движок gnuboard с самописным скином, всё отдаётся обычным HTML.

Отсюда главное отличие от partsfit: **объём мал и не растёт**. На 29.08.2026 —
120 объявлений, 7 страниц по 18. Это не выборка, а вся доска целиком.

Из 15 продавцов **90 объявлений (75%) — от одного номера, самого SkyWheel**, ещё 15 —
от второго. То есть по сути это склад одного дилера с витриной в виде доски, а не
барахолка из сотни частников. Для закупки это хорошая новость, для объёма — нет.

## Что отдаёт донор

Карточка содержит готовую таблицу «поле — значение», и заполнена она у всех 120:

| поле донора | что это | покрытие |
|---|---|---|
| `제조사` | марка | 120/120 |
| `사이즈` | диаметр в дюймах | 120/120 |
| `구분` | новое / б/у | 120/120 (14 новых, 106 б/у) |
| `휠상태` | состояние | 120/120 |
| `판매가격` | цена в 만원 (десятках тысяч вон) | 120/120 |
| `판매지역` | регион продавца | 120/120 |
| `이름`, `연락처` | имя и телефон продавца | 120/120 |

Плюс галерея (420 фотографий, у всех есть, до 5 на объявление) и текст описания.

## Чего донор НЕ отдаёт — и это решает всё

**Параметров подбора почти нет.** Для диска это то же, чем для детали партномер:

| параметр | сколько объявлений |
|---|---|
| ширина обода (J) | 16/120 |
| разболтовка (PCD) | 8/120 |
| вылет (ET) | 15/120 |
| посадочное отверстие (CB) | 5/120 |

Всё это лежит не в полях, а в свободном тексте описания, и большинство продавцов их
просто не пишет. Классификатор достаёт что есть, но строить на этом фильтр подбора
нельзя — он будет пустым у семи объявлений из восьми.

Работающая замена — **марка + модель авто + диаметр**: марка разбирается у 120/120,
модель у 107/120, диаметр у 120/120. Так покупатель диски и ищет («на G80, 19 дюймов»).

## Ловушки

- **Марка в поле донора огрублена.** Genesis лежит под `현대` (Hyundai), Maserati —
  под `수입기타` («импорт, прочее»). Поэтому марка уточняется по заголовку, а поле
  донора остаётся запасным вариантом. Порядок в `BRAND_HINTS` значим: `제네시스`
  обязан проверяться раньше `현대`.
- **Проданное с доски не исчезает.** Продавец дописывает `[판매완료]` в заголовок,
  и объявление висит дальше. Без флага `sold` товар уехал бы на витрину как имеющийся.
- **Позиции всё же пропадают** — насовсем и без следа. Поэтому `data/skywheel/index.json`
  под контролем версий: в нём копятся `firstSeen` и `lastSeen`, повторным прогоном
  их не восстановить. Ушедшие строки из файла не стираются, у них перестаёт двигаться
  `lastSeen` — по нему и видно, что продалось.
- **Таблицу карточки разбирать построчно, а не парой соседних `<td>`.** Заголовок
  секции (`● 휠 정보 ●`) стоит своей строкой одной ячейкой на две колонки, и регулярка
  по паре ячеек через него перескакивает, склеивая заголовок со следующим полем
  и съедая его значение. Ровно так молча пропала цена у всех 120 объявлений.
- **Комплектность распознаётся у 14/120.** «1짝» — одно колесо, «1세트» — комплект
  из четырёх. Цена отличается вчетверо, а большинство продавцов не пишет ни того,
  ни другого. Спрашивать у поставщика поштучно.
- **Фотографии хотлинкаются** — проверены все 420, отдаются с чужим `Referer`.
  Домен `www.skywheel.kr` в `next.config.ts` пока НЕ разрешён: понадобится, если
  пойдём тем же путём, что с partsfit (хотлинк вместо своей копии).

## Марка и модель — только из заголовка

Заголовок объявления говорит, о чём оно. **Описание у кованого афтермаркета
перечисляет список совместимости** — «SW03 встаёт на Kia K9, Carnival, Land Rover…».

Пока классификатор искал марку и модель по обоим текстам, первое попавшееся имя
выигрывало, и на витрине появился товар «Land Rover Carnival»: марка из поля донора,
модель из чужой строки совместимости. Вылезло на первой же сборке страницы.

Цена правки честная: покрытие модели упало со 107 из 120 до 99. Те восемь брались
из списка совместимости и товару не принадлежали.

Параметры подбора и тип диска по-прежнему читаются и из описания: там они про сам
товар, а не про то, на что он встаёт.

## Марки, которые делают диски, а не машины

`SkyWheel`, `BBS`, `Weds` — производители дисков. У остальных позиций марка это машина,
и текст строится вокруг неё («R19, встречается на Genesis G80»); у этих та же фраза
даёт «встречается на SkyWheel», то есть бессмыслицу.

Список закрытый и продублирован в двух местах: `BRAND_HINTS` здесь и `WHEEL_MAKERS`
в `src/lib/shop/wheels-text.ts` (скрипты на `.mjs`, приложение на `.ts`, общего модуля
между ними нет — так же разведены словари partsfit). Появится ещё один производитель —
дописывать в оба, иначе он молча поедет на витрину как марка автомобиля.

## Заливщик только дописывает

`skywheel:load` делает `upsert`, и это правильно: повторный прогон обязан обновлять
цену и признак продажи. Но **строки, исчезнувшие из источника, в базе остаются**.

Поймано на марках: пока одна позиция была без марки, `build-tables` заводил ей `other`;
после правки словаря марка нашлась, а осиротевшая строка `other` в таблице осталась.
На витрину она не попадает (фильтр считает марки по товарам, а не по справочнику),
но при следующей заливке такое надо вычищать руками:

```sql
delete from skywheel_brands b
 where not exists (select 1 from skywheel_wheels w where w.brand_slug = b.slug);
```

## Берём только цену продажи

**Поле `판매가격` ценой продажи является не всегда, и это не мелочь.**

У кованых SW-xx донор ставит в шапку цену `대품시` — со сдачей своих дисков в зачёт, —
а обычную покупку называет строкой `일반 구매` в описании, на 300–400 тысяч вон дороже.
Таких объявлений девять, и у всех девяти поле совпадало именно с зачётной ценой.
Считая наценку от неё, мы продавали бы с фактическим множителем ×1.22–1.31 вместо ×1.5:
около 3 800 долларов недобора маржи на этих девяти позициях.

Хуже того, эти объявления покрывают несколько диаметров сразу, и **поле `사이즈`
у шести из девяти отвечает не тому диаметру, чья цена стоит в шапке**. Пример: `#135`
заявлен как 20″, а цена в шапке — за 18″. Поэтому цена берётся по диаметру, который
мы показываем, а не по порядку в строке.

Формулировок у цены продажи три, и все три надо ловить. Правило `salePrice()`
в `classify.mjs`, по порядку проверки:

| что в описании | что берём | позиций |
|---|---|---|
| `일반 구매` с сеткой по диаметрам | цену **нашего** диаметра | 7 |
| `일반 구매` с одной ценой | её | 2 |
| `대품 없이 220만원` — «без сдачи в зачёт» | её | 6 |
| `판매가 390만원` — «цена продажи» прямо | её, если она не выше поля вдвое | 1 |
| ничего из перечисленного | поле `판매가격` | 103 |
| диаметра нет в сетке продавца | **null → «по запросу»** | 1 (продан) |

Потолок «не выше поля вдвое» у `판매가` — защита от опечатки продавца, а не
перестраховка: в `#98` стоит «판매가 1000만원» при зачёте 90만원, то есть лишний ноль.
Настоящая скидка за сдачу дисков — 300–700 тысяч вон, а не десятикратная разница.

Ловить `대품 없이` регуляркой по `\s` в Python недостаточно: в `#74` между словами
стоит U+FEFF, который питоновский `\s` не матчит, а JS матчит. Проверять разбор
надо самим скриптом, а не отдельным зондом — зонд насчитает на одну меньше.

## НДС заложен в цену

**27 объявлений называют налог отдельно, и его 10% входят в `price_krw`.**
Формулировки две, значат одно — цена в объявлении без налога:

| | позиций |
|---|---|
| `(VAT별도)` — «НДС отдельно» | 13 |
| `카드는 부가세10%입니다` — «картой +10% НДС» | 14 |

Второе формально про способ оплаты: наличными продавец готов не проводить сделку
по документам. Нам это не подходит — закупка идёт по инвойсу, — поэтому налог
закладывается в обоих случаях. **«НДС включён» не пишет ни одно объявление**,
так что обратного случая нет и подкрутить в другую сторону нечего.

Порядок обязателен: **сначала цена продажи, потом налог на неё.** У пяти позиций
иначе НДС лёг бы на зачётную цену. В таблице есть флаг `vat_included` — без него
непонятно, почему наша цена выше той, что стоит в объявлении.

**`null` — штатное значение, а не сбой разбора.** Цена продажи может быть неизвестна,
и тогда витрина пишет «по запросу» и не даёт положить товар в корзину: по этой цене
выставляется счёт, и придумывать её нельзя. `getPricesKrwByCartId` такой товар в карту
цен не кладёт вовсе — иначе `null` дал бы NaN в сумме заявки.

Что в цену **не** идёт и почему:

- **цены `대품` и `교환`** — сдача в зачёт и доплата за обмен. Это не наша сделка;
  у 90 объявлений из 120 они стоят рядом с ценой продажи и сбивают с толку.
- **сетки по диаметрам целиком** — у SW-xx это прайс на 2–4 товара, а не одна цена.
- **оценки продавца** — «с шинами это тянет на 350만원» при цене 100만원 (`#167`)
  или «продаю по этой цене только 5 дней». Это разговор, а не цена.

Что осталось за пределами разбора: у `#56` продавец обещает 10% скидки тому,
кто сошлётся на его доску. Это скидка конечному покупателю в Корее, к нашей
закупке отношения не имеет.

## Десять объявлений — не один товар

У 10 позиций в описании перечислено несколько диаметров со своей ценой на каждый:
кованые SW-xx самого SkyWheel идут в 19, 20, 21 и 22 дюймах, от 230 до 340 тысяч вон.
Поле `사이즈` при этом называет только один. Разложить такое объявление на товары
автоматически нельзя — цены лежат прозой; либо заводить руками, либо не брать.

И там же вторая ловушка: у кованого афтермаркета марка и модель — это **совместимость,
а не происхождение**. SW-15 подходит и к BMW E92 M3, и к F-серии, и к Kia Carnival;
классификатор запишет ему одну марку. Правило partsfit действует и здесь: подписывать
«встречается на этих машинах», а не «подходит к».

## Чего в выходном файле нет намеренно

- **Имени и телефона продавца.** Это чужие персональные данные с чужой доски: они
  нужны закупщику, а не витрине. В `wheels.json` остаётся только `sellerRef`
  (`seller-1`, `seller-2`…) — видно, что позиции от одного продавца, без самого номера.
  Телефоны есть в `items.json`, который в гит не идёт.
- **Рублей и долларов.** Цена только в вонах. Пересчёт и наценка — дело
  `lib/shop/pricing.ts`, и второго места для наценки быть не должно.

## Что идёт в описание

Решение владельца от 29.08.2026: **название, марка или производитель, модель
и характеристики, если продавец их назвал.** Больше ничего.

Убрано и возвращать не надо:

- **оговорка «разболтовку и вылет продавец не указал — уточним по запросу»**. Она
  стояла у семи товаров из восьми и превращала описание в извинение. Нет параметров —
  молчим, у товара остаются название, марка и диаметр.
- **оговорка «совместимость указана по объявлению продавца, сверьте со своей машиной»**
  под описанием. Формулировку «встречается на» мы и так не заменяем на «подходит к» —
  осторожность уже в ней, второй раз повторять незачем.
- **пояснения про тип диска** («кованый легче литого при той же прочности») — реклама,
  а не факт, и тип уже назван в заголовке.
- **состояние и оценка продавца** — они не проза. Состояние показывается плашкой
  на карточке, оценка — строкой в таблице характеристик страницы товара.
  Пустая оценка подписывается «не указана»: молчание донора читается как «хорошее»,
  а такого он не говорил.

Комплектность и шины остались: это характеристики того, что продаётся. Комплектность
особенно — цена комплекта и штуки отличается вчетверо.

## Заголовки донора пишутся и слитно, и раздельно

`제네시스 g90` и `제네시스g90` — одно и то же, и словарь обязан ловить оба. Сравнение
в `classify.mjs` идёт по строке без пробелов с обеих сторон. Пока этого не было,
«제네시스g90» не находил модель G90 и падал в общий запасной вариант словаря,
давая на витрине **«Genesis Genesis»**. Голого `제네시스` в словаре моделей поэтому
больше нет: марка уже Genesis, и модель «Genesis» дублировала её.

## Описания донора к публикации не годятся

Текст описания есть у всех 120, но это **объявление продавца, а не карточка товара**.
Внутри — реклама собственных точек SkyWheel («работы можно сделать в Кимпхо
и Намянджу»), скидка за упоминание доски, цена за наличные против карты с НДС 10%,
цена обмена и trade-in. Всё это условия чужой розницы в Корее, которых мы не даём.

Публиковать такие описания как есть нельзя. Варианта два: собирать описание из полей
(тип диска + марка + модель + диаметр + состояние), как это сделано в partsfit,
либо переписывать вручную — на 120 позициях это подъёмно.
